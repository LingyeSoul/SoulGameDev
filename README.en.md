# SoulGameDev

![License: MIT](https://img.shields.io/badge/license-MIT-blue)
![Python 3.12+](https://img.shields.io/badge/python-3.12%2B-3776AB?logo=python&logoColor=white)

> One asset, one generator. Data separated from drawing. Verified at build time. Byte-identical on rebuild.

SoulGameDev is an agent skill and a copyable project template for **deterministic content production** in small game teams. The workflow comes from a Godot 4.7 2.5D pixel roguelike that shipped with every sprite, tile, UI panel, VFX frame, SFX, ambience loop, and music stem generated by Python: no external images, no sample packs. The template ships a Pillow pixel pipeline, an `svgwrite` + `CairoSVG` vector pipeline, a default-installed SpriteKiln pipeline for 8-direction characters, and a synthesizer/numpy/scipy + pyo audio pipeline. Before generating a new character or enemy asset, the skill asks whether to use SpriteKiln.

Generated content should behave like software: small modules, explicit contracts, deterministic output, and checks that fail the build.

## The rules

| Rule | Why it matters |
| --- | --- |
| One output asset = one Python module | Regenerate a single sprite without rebuilding everything. A failure names one file. |
| Drawing code never contains game data | Palettes, frame tables, BPM, durations, and peaks live in `_data/`. |
| `build.py` only orchestrates | It discovers modules, imports them, merges metadata, and writes the manifest. It never draws or synthesizes. |
| Every module verifies its output | Wrong size, palette, peak, or loop seam fails the build. Local artifacts are for diagnosis only and must not ship. |
| Two consecutive builds are byte-identical | Generated assets can be diffed, reviewed, and versioned like source. |
| Manifests are the runtime API | The game reads `atlas.json` and `audio.json`; it never walks the art directory. |

## What's in the box

- `tools/art/build.py`: discovers every module under `tools/art/`, calls `build(root)`, merges metadata into `art/_meta/atlas.json`, and can write 4x previews.
- `tools/audio/build.py`: the same for `tools/audio/` and `art/_meta/audio.json`.
- `_lib/`: Canvas, outline, bevel, sprite sheets, SVG canvas, CairoSVG rasterization, envelopes, noise, filters, pyo offline rendering, loop construction, and verification.
- `_data/`: palettes, animation tables, vector colours, audio profiles, and pyo profiles.
- Three sample art modules (two pixel + one SVG) and three default audio modules (including pyo), each fully verified.
- `scripts/scaffold.py`: copies the template into an existing repository and refuses to overwrite files.
- `assets/project-template/scripts/kiln_import.py`: after scaffolding it lives at the project's `scripts/kiln_import.py` and imports a SpriteKiln 8-direction render into `art/_meta/spritekiln.json`; the skill asks before using SpriteKiln for a new character.
- `tools/audio/sfx/pyo_impact.py`: a pyo offline DSP example, included in the default audio build.
- `references/`: pipeline rules, acceptance gates, and the Windows / Web / Android delivery checklist.

```bash
npx skills add LingyeSoul/SoulGameDev -g -y

```

From a local checkout:

```bash
npx skills add <path-to-this-repo> -g -y --copy
```

Once installed, the skill is available to your agent as `SoulGameDev`. `npx skills add` installs skills only; it does not install Python packages or prerequisite skills.

### Prerequisites

- Python 3.12+.
- Pillow, numpy, scipy, soundfile, synthesizer, svgwrite, CairoSVG, pyo, and SpriteKiln:

```bash
python -m pip install Pillow numpy scipy soundfile "synthesizer>=0.4" svgwrite CairoSVG "pyo>=1.1,<2" "spritekiln[mcp]>=0.3,<0.4"
```

On Windows, if CairoSVG cannot load cairo, install the GTK 3 runtime; see section 6.6 of `references/art-pipeline.md`. After scaffolding, prefer `python -m pip install -r requirements.txt`.

Or, after scaffolding, use the version ranges:

```bash
python -m pip install -r requirements.txt
```

- The `awesome-gamedev-agent-skills` pack (`router`, `create-game-assets`, `audio-design`, `game-feel`, `godot-*`). SoulGameDev reuses those skills instead of duplicating them. Check with `npx skills list -g`; install the pack separately if it is missing.
- Optional: Godot 4.x. The template produces assets, not engine code.
- `spritekiln[mcp]>=0.3,<0.4` is a default dependency, already in `requirements.txt`; installing it makes the `spritekiln` command available. You can also install it globally with `uv tool install "spritekiln[mcp]"`.
- `pyo>=1.1` is a default audio dependency and requires Python 3.12+; it is already in `requirements.txt`.

## Quick start

```bash
# Copy the template into an existing game repository (refuses to overwrite)
python <skill-dir>/scripts/scaffold.py --into <project-root> --dry-run
python <skill-dir>/scripts/scaffold.py --into <project-root>

cd <project-root>
python -m pip install -r requirements.txt

# Build the sample assets (including pyo)
python tools/art/build.py --root . --preview
python tools/audio/build.py --root .

# Validate imported SpriteKiln manifests and files (safe no-op before any import)
python scripts/kiln_import.py --root . --check
# Fail when the project requires SpriteKiln assets but the manifest is missing
python scripts/kiln_import.py --root . --check --require-manifest

# Rebuild one asset
python tools/art/build.py --root . --only actors/player
python tools/audio/build.py --root . --only sfx/hit
python tools/audio/build.py --root . --only sfx/pyo_impact

# Run one generator directly (writes its file, skips the manifest)
python tools/art/actors/player.py
python tools/audio/sfx/hit.py
python tools/audio/sfx/pyo_impact.py
```

Expected output:

```text
art/actors/player.png             64x24 sheet, four 16x24 frames
art/ui/panel.png                  32x32 UI panel
art/vector/sigil.svg              64x64 SVG source
art/vector/sigil.png              128x128 CairoSVG raster
art/audio/sfx_hit.wav             0.2 s, SFX bus
art/audio/ambience_room.wav       8.0 s seamless loop, Music bus
art/audio/sfx_pyo_impact.wav      0.24 s, SFX
art/_meta/atlas.json              sheets + images + vectors
art/_meta/audio.json              clips + bus + loop flag
art/_meta/preview_*.png           4x previews (with --preview)
art/_meta/spritekiln.json         8-direction manifest after a SpriteKiln import
art/sprites/<name>/qa.json        SpriteKiln QA record after an import
```

## One asset, one module

```text
tools/art/actors/player.py          -> art/actors/player.png
tools/art/vector/sigil.py           -> art/vector/sigil.svg + art/vector/sigil.png
tools/art/tiles/layer_01_floor.py   -> art/tiles/layer_01_floor.png
tools/audio/sfx/hit.py              -> art/audio/sfx_hit.wav
tools/audio/ambience/layer_02.py    -> art/audio/ambience_layer_02.wav
tools/audio/sfx/pyo_impact.py       -> art/audio/sfx_pyo_impact.wav
```

- A sprite sheet is one output. Variants (warm flame / blue flame, normal / elite, intro / death) are separate modules that share `_lib` and `_data`.
- Before generating a new character or enemy asset, ask whether to use SpriteKiln (8-direction/side-view skeletal animation); do not run SpriteKiln by default.
- `_lib/` holds generic capabilities only, never game content.
- `_data/` holds palettes, animation tables, vector colours, BPM, root notes, durations, and peaks.
- A vector module writes one `.svg` source and one CairoSVG-derived `.png`; the PNG is registered in the `vectors` manifest.
- Adding an asset means adding a file; you never edit `build.py`.
- `--only` regenerates the selected modules and merges them into the existing manifest, leaving other assets untouched.

## Contracts

The reference project uses a 640x360 native canvas, 16x16 tiles, and 16x24 characters with a bottom-center pivot. The sample character module fixes the 16x24 cell and enforces the palette subset, 1 px outline, bottom row, and color count; change those constants when your contract differs.

**Pixels**: integer-only drawing, palette-first colors, 1 px ink outline, two-step internal shading, no antialiasing, gradients, blur, or fractional scaling. The bottom row of every character frame must contain opaque pixels.

**Vectors**: SVG must declare explicit width and height; colors come only from `VECTOR_PALETTE`; external references, `<image>`, scripts, `<style>`, `<text>`, `<use>`, filters, gradients, and patterns are rejected. Antialiasing is expected; the PNG is produced by CairoSVG at build time with size = SVG × a positive integer scale.

**SpriteKiln**: YAML is the source; `render` must write a `qa.json` with `ok: true`; 8-direction characters are imported by `kiln_import.py` into `art/_meta/spritekiln.json`, never mixed into `atlas.json`.

**Audio**: 22050 Hz, mono, PCM16. Every clip declares a bus (`SFX`, `Music`, or `Master`) and whether it loops. Looping clips must pass a seam check; one-shot clips still pass format, peak, duration, and boundary-amplitude checks. pyo is a default dependency (Python 3.12+) and uses the same `verify_audio` gates.

## Verification

Every module calls `verify_sprite`, `verify_vector` / `verify_raster`, or `verify_audio` inside `build(root)`. A failed check raises with the asset path, so CI fails and no invalid file is published. pyo modules additionally reject a `None` graph return and silent renders.

Determinism is checked with two builds. Fingerprint `art/` (this includes the manifests), rebuild, fingerprint again, and compare:

```bash
python -c "import hashlib,pathlib;[print(hashlib.sha256(p.read_bytes()).hexdigest(), p.as_posix()) for p in sorted(pathlib.Path('art').rglob('*')) if p.is_file()]"
```

Run that before and after:

```bash
python tools/art/build.py --root . --preview
python tools/audio/build.py --root .
```

The two lists must be identical.

Acceptance gates:

- [ ] Size, palette, outline, bottom row, and color count pass.
- [ ] SVG structure, vector palette, and derived PNG size/alpha pass.
- [ ] Sample rate, channels, bit depth, peak, duration, and loop seam pass.
- [ ] pyo modules pass the same audio gates.
- [ ] SpriteKiln `qa.json` is `ok: true`, and `spritekiln.json` loads.
- [ ] PNG / SVG / WAV / JSON bytes are identical across two builds.
- [ ] `atlas.json`, `spritekiln.json`, and `audio.json` load by key at runtime.

## Manifests

`art/_meta/atlas.json`:

```json
{
  "sheets": {
    "player": {
      "path": "res://art/actors/player.png",
      "cell": [16, 24],
      "pivot": [8, 23],
      "animations": {
        "idle": { "fps": 6, "frames": [[0, 0], [0, 1]], "loop": true },
        "walk": { "fps": 8, "frames": [[0, 2], [0, 3]], "loop": true }
      }
    }
  },
  "images": {
    "panel": "res://art/ui/panel.png"
  },
  "vectors": {
    "sigil": {
      "svg": "res://art/vector/sigil.svg",
      "raster": "res://art/vector/sigil.png",
      "size": [64, 64]
    }
  }
}
```

`art/_meta/audio.json`:

```json
{
  "clips": {
    "hit":  { "path": "res://art/audio/sfx_hit.wav", "bus": "SFX", "loop": false },
    "room": { "path": "res://art/audio/ambience_room.wav", "bus": "Music", "loop": true }
  }
}
```

`art/_meta/spritekiln.json` (written by `scripts/kiln_import.py`):

```json
{
  "format": 1,
  "sprites": {
    "knight": {
      "sheet": "res://art/sprites/knight/knight.png",
      "atlas": "res://art/sprites/knight/knight.json",
      "normal": "res://art/sprites/knight/knight_normal.png",
      "emissive": "res://art/sprites/knight/knight_emissive.png",
      "cell": [96, 96],
      "pivot": [48.0, 68.41],
      "directions": ["s", "se", "e", "ne", "n", "nw", "w", "sw"],
      "view": "topdown",
      "animations": {
        "idle": {
          "loop": true,
          "directions": {
            "s": { "row": 0, "frames": [[0, 0]], "durations": [150], "events": {}, "sockets": {} }
          }
        }
      }
    }
  }
}
```

At runtime, build `SpriteFrames` / `AtlasTexture` from the atlas, let an audio manager load clips by key, and load 8-direction characters by action + direction from `spritekiln.json`. Manifest paths use `res://` because the workflow comes from Godot; change the prefix and write a small loader for another engine.

## Delivery

Before shipping, run the checklist in `references/ship-and-verify.md`: headless content and connectivity tests, an end-to-end run, smoke screenshots, and at least one launch each on Windows, Web, and Android.

Web needs extra care: export single-threaded or serve correct COOP/COEP headers, make sure `.wasm` is served as `application/wasm`, bundle CJK fonts, and ship OGG loops instead of WAV masters.

## FAQ

**Do I need Godot?**
No. The template emits PNG, WAV, and JSON. Manifests use `res://` because the workflow came from Godot; change the prefix and add a loader for your engine.

**Can I keep my existing generator?**
Yes. Migrate one output at a time: split a module out, move its numbers into `_data/`, rebuild twice, and compare hashes. Each reference describes the migration order.

**What if scaffolding finds existing files?**
It aborts and lists every conflict. Nothing is overwritten. Run with `--dry-run` first.

**Can I hand-edit files under `art/`?**
No. The next build overwrites them. Edit the module or `_data/` and regenerate.

**When should I use SVG, and when SpriteKiln?**
Use SVG for UI, icons, and logos; use SpriteKiln for 8-direction skeletal characters with events and sockets; keep pixel characters and tiles on Pillow. All three coexist, but their manifests stay separate: `atlas.json` for pixel/vector assets, `spritekiln.json` for 8-direction characters.

**Does the skill force SpriteKiln for characters?**
No. Before a new character or enemy, the skill asks whether to use SpriteKiln (8-direction/side-view skeletal animation) or regular Pillow/SVG, and only then picks the pipeline.

**When should I use pyo, and when synthesizer?**
Use synthesizer + numpy/scipy for short SFX, simple tones, noise beds, and loops; use pyo for complex multi-stage filters, granular work, delays/reverbs, or parameter curves. pyo requires Python 3.12+ and is part of the default dependencies and default audio build.

**Why 22050 Hz mono?**
It keeps SFX and ambience small and is enough for this style. If you need 44.1 kHz stereo, change the contract and its checks together.

**Does this replace the other gamedev skills?**
No. SoulGameDev owns deterministic content production and verification. Use `router`, `create-game-assets`, `audio-design`, `game-feel`, and `godot-*` for art direction, mixing, game feel, and engine details.
